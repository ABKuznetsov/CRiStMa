# Structure Core: symmetry-expanded identity and periodic geometry

Date: 2026-08-30

Status: approved design for an internal milestone

## 1. Purpose

This milestone establishes the finite atomic representation on which geometry,
coordination, polyhedra, diffraction, transforms, and refinement will depend.
It must preserve the distinction between:

```text
crystallographic position
chemical occupation of that position
symmetry expansion within the reference cell
periodic images in translated cells
```

The completed scientific path is:

```text
structure file
     |
     v
CrystalStructure
     |
     v
space-group expansion
     |
     v
AtomicView of unique reference-cell positions
     |
     v
PeriodicNeighborGraph
     |
     v
CoordinationEnvironment
```

This is an internal development milestone, not the public `0.1.0` release.
CRiStMa remains a development package until its API has been exercised by at
least Viewer and Finder on real data. The first public release is prepared only
after those integrations and a public-API stabilization pass.

## 2. Position and occupation model

`IndependentSite` represents one independent crystallographic position and its
occupation model:

```text
IndependentSite
|- id
|- label
|- fractional
|- components: tuple[SiteComponent, ...]
`- displacement
```

Each `SiteComponent` contains a chemical species and its occupancy:

```text
SiteComponent
|- species
`- occupancy
```

The following invariants apply:

```text
0 <= component.occupancy <= 1
sum(component.occupancy) <= 1
vacancy_fraction = 1 - sum(component.occupancy)
```

Vacancy fraction is a derived value and does not create an atom or a special
vacancy component. A site with mixed chemical occupancy remains one geometric
position. A change in component fractions does not change that position's
identity.

`SiteComponent` has no coordinates. Components reported at different
coordinates are positional or split disorder and therefore belong to distinct
`IndependentSite` positions. Future disorder-group types may relate those
positions without changing this invariant.

## 3. ExpandedAtom

`ExpandedAtom` represents one unique space-group-expanded geometric position
inside the reference unit cell:

```text
ExpandedAtom
|- id
|- structure_id
|- source_site_id
|- fractional
|- cartesian
|- components
|- displacement
|- representative_operation_id
`- equivalent_operation_ids
```

The expansion copies the occupation and displacement model of the source site.
It does not split mixed occupancy into coincident atoms.

A special position may be generated by several symmetry operations. Equivalent
generated positions are merged into one `ExpandedAtom`; all generating
operation IDs are retained. The representative operation is provenance and is
not itself the atom's identity.

Expanded-atom identity is determined by:

```text
structure identity
+ source-site identity
+ canonical symmetry-expanded position in the reference cell
```

Chemical species and component occupancy are excluded from identity. Numeric
canonicalization and tolerance policy are explicit inputs to expansion, so ID
generation is deterministic under that policy.

The existing internal name `ExpandedAtomRef` is replaced by `ExpandedAtom`
before any public release. No compatibility alias is required for the internal
development API.

## 4. PeriodicAtomRef

Space-group expansion and lattice translation are separate operations.
`ExpandedAtom` never represents the infinite copies in neighboring cells.

```text
PeriodicAtomRef
|- atom_id
`- cell_translation: tuple[int, int, int]
```

`PeriodicAtomRef` is a lightweight reference, not an independent atom. Its
fractional and Cartesian coordinates are computed from the referenced atom,
cell, and integer translation. They are not stored in the reference.

```text
ExpandedAtom = which unique reference-cell position
PeriodicAtomRef = which translated image of that position
```

The same reference type may be used by neighbor graphs, polyhedra, supercell
views, and visualization without inserting periodic copies into the canonical
structure or atomic view.

## 5. AtomicView

`AtomicView` is the finite, immutable, numerical representation of one
structure at a chosen expansion policy:

```text
AtomicView
|- atoms: tuple[ExpandedAtom, ...]
|- fractional: ndarray[n, 3]
|- cartesian: ndarray[n, 3]
|- cell: ndarray[3, 3] | None
`- periodic: tuple[bool, bool, bool]
```

The arrays are read-only and row-aligned with `atoms`. A crystalline view
contains the unique symmetry-expanded positions of the reference cell only.
Periodic images are produced on demand through `PeriodicAtomRef`.

The current single-species-per-row representation is removed because it cannot
represent mixed occupancy. Chemical occupation is available through:

```python
view.atoms[index].components
```

An `AtomicView` may still carry additional row-aligned `AtomicPropertyTable`
data. Such derived properties do not replace canonical identity, coordinates,
components, or displacement information.

## 6. Periodic neighbors

`PeriodicNeighbor` describes a directed relation from an atom in the reference
cell to an image of a target atom:

```text
PeriodicNeighbor
|- source_atom_id
|- target: PeriodicAtomRef
|- distance
|- vector_fractional
`- vector_cartesian
```

The source is implicitly in cell `(0, 0, 0)`. A reverse relation has the
opposite vector and the translation required to view the original source from
the target's reference cell.

`PeriodicNeighborGraph` contains a finite node set and explicit periodic
edges:

```text
PeriodicNeighborGraph
|- atoms: tuple[ExpandedAtom, ...]
|- neighbors_by_atom
`- diagnostics
```

Graph nodes are unique geometric positions, not position-component pairs.
Consequently mixed occupancy does not create zero-length edges, duplicate
neighbors, or inflated coordination numbers.

The graph preserves periodic self-neighbors when scientifically valid. Edge
identity includes the target atom and target cell translation, so two images of
the same reference-cell atom remain distinct neighbors.

## 7. NeighborFinder and coordination

The initial configurable tool is:

```python
graph = NeighborFinder(
    cutoff=3.0,
).find(view)
```

It accepts a finite `AtomicView`, enumerates only the lattice translations
needed by the selected search policy, and returns a
`PeriodicNeighborGraph`. Configuration is stored by the finder; calculation
state is returned explicitly.

The first implementation provides an exact distance-cutoff method. Chemistry-
dependent policies such as covalent radii and bond-valence selection are added
as independent policies after the periodic geometry is verified.

`CoordinationAnalyzer` consumes an atomic view and periodic neighbor graph and
returns explicit `CoordinationEnvironment` results. Geometric coordination is
computed per position. Chemical interpretations may inspect all
`SiteComponent` values and report weighted component contributions without
altering graph topology.

## 8. Public usage shape

The intended consumer-facing composition is:

```python
from cristma import read_structure
from cristma.geometry import NeighborFinder
from cristma.symmetry import expand_structure

crystal = read_structure("sample.cif")
view = expand_structure(crystal)
graph = NeighborFinder(cutoff=3.0).find(view)
```

Exact convenience names may be aligned with the existing top-level I/O API
during implementation. The scientific return types and invariants in this
document are the stable design requirements.

## 9. Diagnostics and failure behavior

Programmer errors and invalid object construction raise exceptions. Scientific
or source-dependent conditions are returned as structured diagnostics. At
minimum, diagnostics cover:

- invalid or non-invertible cells;
- invalid occupancy totals;
- incomplete or fallback symmetry;
- positions merged within the selected tolerance;
- ambiguous atom identity after canonicalization;
- cutoffs or search bounds that cannot be evaluated safely;
- non-finite coordinates, distances, or vectors.

No algorithm silently drops a component, symmetry-equivalent position,
periodic edge, or failed calculation.

## 10. Verification

The milestone is complete when tests establish:

- P1 expansion preserves every independent site exactly once;
- general positions expand to the expected multiplicity;
- special-position duplicates merge and retain all generating operations;
- mixed occupancy creates one expanded position with all components;
- split positions remain distinct;
- occupancy totals and vacancy fractions obey their invariants;
- Cartesian and fractional coordinates agree with the unit-cell matrix;
- periodic references resolve to the correct translated coordinates;
- graph edges have correct reverse vectors and translations;
- boundary-crossing neighbors are found without duplicating graph nodes;
- coordination numbers are invariant under equivalent choices of reference
  cell;
- real CIF and SHELX fixtures traverse the complete structure-to-neighbor path;
- the built wheel exposes the intended imports in a clean environment.

No public PyPI publication is part of this milestone.
